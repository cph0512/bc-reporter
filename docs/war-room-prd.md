# 戰情室產品規格

## 目標

建立一套公司經營戰情室，讓管理層可以用五年財務預測作為經營基準，持續比對 ERP 實績、業務機會與潛力客戶開發成果，並固定輸出月報、季報、年報。

## 核心場景

1. 管理層維護未來五年 forecast，並可針對不同情境版本做調整。
2. 系統從 ERP 匯入實績資料，自動比對 forecast 與 KPI 達成率。
3. 業務主管追蹤 pipeline、訂單、回款與潛在客戶開發，評估缺口補足策略。
4. 系統定期輸出月報、季報、年報，供經營會議使用。

## 模組拆解

### 1. Forecast 管理

- 支援五年 forecast 編修。
- 支援版本管理：
  - Base
  - Stretch
  - Conservative
  - 自訂 Scenario
- 支援維度切分：
  - 年 / 季 / 月
  - BU / 產品線 / 地區 / 客戶別
  - 營收 / 毛利 / 費用 / 現金流 / 資本支出
- 支援調整方式：
  - 直接輸入
  - 套用成長率
  - 以 driver 反推
  - 批次複製情境

### 2. ERP 串接與 KPI 計算

- 從 ERP 拉入實績：
  - 訂單
  - 出貨
  - 開票
  - 應收
  - 回款
  - 存貨
  - 成本
  - 費用
- 建立資料對應層：
  - ERP 科目或單據欄位
  - 戰情室科目
  - KPI 口徑
- KPI 計算結果至少包含：
  - 營收達成率
  - 毛利率
  - 費用率
  - EBITDA
  - 現金回收率
  - 應收帳款週轉
  - 存貨週轉
  - 業務 pipeline coverage

### 3. 業務模組與潛力客戶找尋

- Forecast 缺口要能連動業務模組。
- 業務模組至少要有：
  - 客戶
  - 潛在客戶
  - 商機
  - 拜訪紀錄
  - 預估成交月份
  - 成交機率
  - 預估營收與毛利
- 潛力客戶來源可整合台股分析資料：
  - 產業分類
  - 營收成長
  - 資本支出
  - 擴產訊號
  - 法說會重點
  - 公開財報摘要
- 戰情室要能回答：
  - 哪些 forecast 缺口需要新客戶補
  - 哪些潛力客戶最值得優先開發
  - 現有 pipeline 是否足以支撐年度目標

### 4. 報表中心

- 固定輸出：
  - 月報
  - 季報
  - 年報
- 報表內容至少包含：
  - 實績 vs forecast
  - KPI 達成率
  - 差異分析
  - 業務 pipeline
  - 潛力客戶清單
  - 風險與行動項
- 報表產出方式：
  - Web dashboard
  - 匯出 PDF
  - 匯出 Excel
  - Email 定時發送

## 使用者角色

- CEO / GM：看整體達成率、差異、風險、行動。
- CFO：維護 forecast、檢查財務口徑、產出經營報表。
- 業務主管：管理 pipeline、分配缺口、追蹤潛在客戶。
- 財會或 IT：維護 ERP 對應與資料同步。

## 建議系統架構

### 前台

- Dashboard 首頁：
  - 本月 / 本季 / 本年 KPI
  - Forecast vs Actual
  - 差異熱區
  - Pipeline coverage
  - 潛力客戶雷達
- Forecast 編輯頁：
  - 試算表風格編輯
  - Scenario 切換
  - Driver 調整
  - 差異即時重算
- 業務缺口頁：
  - 目標缺口
  - 現有 pipeline
  - 潛力客戶推薦
- 報表中心：
  - 月報 / 季報 / 年報模板
  - 排程記錄
  - 匯出與寄送記錄

### 後台服務

- ERP Connector：接 ERP API、DB 或檔案匯入。
- KPI Engine：依口徑重算達成率與差異。
- Forecast Engine：處理 scenario、driver、roll-up。
- Lead Intelligence Service：整理台股資料並計算客戶潛力分數。
- Reporting Service：定時產生報表與寄送。
- Audit Log：記錄 forecast 調整與資料同步歷程。

## 關鍵流程

### 流程 1：調整 forecast

1. 使用者開啟 Base Scenario。
2. 修改某產品線未來 12 個月營收與毛利率假設。
3. 系統即時重算年度營收、毛利、費用率、缺口。
4. 使用者另存為 Stretch Scenario。

### 流程 2：ERP 實績回寫

1. 排程每日或每小時從 ERP 取數。
2. 實績寫入 actuals 表。
3. KPI Engine 依期間與維度重算達成率。
4. Dashboard 更新紅黃綠燈狀態。

### 流程 3：缺口轉成業務任務

1. 系統發現某 BU 年度 forecast 尚差 18%。
2. 業務模組列出目前 pipeline coverage 僅 0.7x。
3. 台股分析模組推薦同產業高成長潛力公司。
4. 業務主管將推薦名單轉成潛在客戶開發清單。

### 流程 4：固定產報

1. 每月結帳後觸發月報。
2. 系統套用月報模板。
3. 匯入 KPI、差異、pipeline 與風險摘要。
4. 自動輸出 PDF / Excel 並寄送指定名單。

## 建議 MVP 範圍

### 第一階段

- 單一公司別
- 單一 ERP 資料來源
- Forecast 編輯與版本管理
- 實績比對與核心 KPI
- 月報產出

### 第二階段

- 業務 pipeline 模組
- Forecast 缺口與 pipeline coverage 連動
- 潛在客戶池管理
- 季報與年報模板

### 第三階段

- 台股分析資料整合與客戶潛力分數
- 多 BU / 多法人別
- 權限控管與審核流程
- 預警通知與 AI 摘要

## 開發順序建議

1. 先定義財務口徑與 KPI 公式。
2. 先完成 forecast editable model。
3. 再接 ERP actuals 與差異計算。
4. 再做業務 pipeline 與缺口連動。
5. 最後做固定報表排程與外部資料推薦。

## 上線前必答問題

- ERP 是哪一套，怎麼取數。
- Forecast 維度要細到 BU、產品線、地區還是客戶。
- KPI 公式是否已有公司內部口徑。
- 台股分析資料來源要用公開資料、商業資料庫，還是自建爬整。
- 月報、季報、年報的模板目前是否已有既有格式。
